- Root-caused the build failures blocking both the device and simulator targets:
  1. The WorkBuddy shell puts `rm`/`cp`/`mv`/`sed`/`find` shims on `PATH`
     (`.../cli/vendor/shim/brokered-bin`, `.../safe-bin`). Xcode's CocoaPods script
     phases inherit that `PATH`, so `Pods-Runner-resources.sh` failed with a bare
     `Unexpected failure`. Builds must run with a sanitised
     `PATH="/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin"`.
  2. Flutter 3.44 + Xcode 27: Flutter calls `lipo -verify_arch arm64 x86_64` in one
     command, which Xcode 27 rejects, failing `debug_unpack_ios`. Patching Flutter's
     `darwin.dart` source does nothing (it runs from a prebuilt snapshot). Fixed by
     adding `EXCLUDED_ARCHS[sdk=iphonesimulator*] = $(inherited) x86_64` to
     `kbi_technician_app/ios/Flutter/Debug.xcconfig`.

  With both in place, `flutter build ios --simulator` succeeds (17.7s incremental) and
  `flutter run` on the iPhone 17 Pro simulator reconnects with hot reload working.
